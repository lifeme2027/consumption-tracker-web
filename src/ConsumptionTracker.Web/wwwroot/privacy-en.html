What this is

A plain record-keeping tool for everyday spending and medication (name, price, quantity, category, date, batch, person taking the medication, dose, notes). It involves no payments, transfers or transactions and never reads your wallet balance. The main app interface is currently in Chinese (import / upload / download messages can be switched to English); this notice is the authoritative English description.

Two modes: local by default, cloud only if you sign in

The top of the page always shows whether you are in Local mode or Cloud mode. Every feature works without signing in; signing in with a Kaspa wallet is optional. The two modes are independent: nothing is synced automatically.

Local mode (default, no sign-in)

  • Your data stays in your browser (IndexedDB) and is never sent to the server. Entering, viewing, editing, deleting, statistics, import and export all run inside the browser; the page submits no records to this site.
  • If you clear browser data, use a private window, or switch browser or device, the data is gone and we cannot recover it for you. Please export a backup regularly (Data tab).
  • Anyone who can open this browser on this computer can see the data. Do not use it on a shared computer, or delete your data after use.
  • Medication names, the person taking the medication, doses and notes are health-related sensitive information. In Local mode they exist only in your browser: there is no account, no session, and this site holds no copy. JSON / CSV files you export are not encrypted; keep them safe.
  • Deleting locally: “Delete all data” on the Data tab removes the data from the browser’s IndexedDB. The browser’s storage engine and the disk underneath may keep fragments of deleted content for some time, which we cannot control. Export files you already downloaded and data in other browsers or on other devices are not deleted.
  • Local mode has no account and no session, so session lifetime and server backups do not apply. Opening the page only requests the page files themselves (see “Server access logs” below).

Cloud mode (optional, after signing in with a Kaspa wallet)

  • After you sign in, your records are stored in this site’s server database. They are not shared, not sold, and not used for advertising; there are no third-party analytics scripts.
  • Data is isolated by Kaspa address: each address can read and write only its own data, and the server checks ownership on every read and write.
  • Data is stored on the server without end-to-end encryption. The server can read the plaintext, and the server administrator can technically access the database file. Do not put information in notes or other fields that you do not want stored on a server.
  • An address is not anonymity: your Kaspa address is a public on-chain identifier and this site stores it to tell accounts apart. We do not promise anonymity.
  • Nothing is synced automatically after sign-in. Local and cloud data are separate. Data moves between them only when you press “Upload local data to account” or “Download from account to local” on the Data tab (each asks for confirmation and explains merge vs. overwrite).
  • “Leave cloud” revokes the session and returns to Local mode; local data is left as it was.
  • Medication names, the person taking the medication, doses and notes are health-related sensitive information. In Cloud mode they are stored in plaintext on the server (see above, no end-to-end encryption). If you are not comfortable with that, use Local mode or leave those fields empty.

Cloud mode: session lifetime

  • A session lasts a fixed 12 hours after sign-in. It is not extended by continued use; after it expires you sign in again by signing with your wallet.
  • “Leave cloud” revokes the session immediately. The server stores only a hash of the session token, never the token itself.
  • “Delete all data” does not end the current session (sessions and data are separate); press “Leave cloud” to end it.

Cloud mode: what deletion actually does

Single-record delete and “Delete all data” really delete, but we do not overstate the effect. Precisely:

  • secure_delete: the database runs with SQLite’s secure_delete, so the content of deleted records is overwritten with zeros inside the database pages instead of merely being marked free.
  • checkpoint: right after “Delete all data” the server merges the write-ahead log (WAL) back into the main database and truncates it, so deleted content does not linger in the log file. The server also does the same every hour, so content from single deletes is cleared from the log within about an hour.
  • Periodic VACUUM: about every 24 hours the server runs VACUUM, which rewrites the whole database file and drops free pages so the file no longer holds old page contents.
  • What is not deleted: backup copies that already exist on the server (including plaintext copies of the database made before you deleted) are not modified when you delete; export files you already downloaded are not deleted; and low-level residue we cannot control (SSD wear levelling, system snapshots, etc.) may remain. So deletion is not an absolute guarantee, and we do not promise one.

Cloud mode: server backups and retention

  • The administrator may back up the server database file. Backups are plaintext (like the database itself, there is no end-to-end encryption).
  • Backups, including old ones, are cleaned up by the administrator by hand. We do not promise automatic cleanup or any specific retention period. Data you delete in the cloud can therefore still exist in backups that were made earlier, until the administrator deletes those backups; the program does not delete them for you.
  • Backups are used only for disaster recovery and are not shared with third parties.

Server access logs (IIS logs)

  • In either mode, opening this site makes the IIS web server in front of the application write ordinary access logs: time, your IP address, the requested URL path, status code and your browser’s User-Agent.
  • These logs do not contain your record content (names, notes, person, dose, etc.): that is sent in request bodies, and keyword search also uses the request body, never the URL. They can show that an IP address visited the site or called an endpoint at a given time.
  • IIS logs are likewise cleaned up by the administrator by hand; we do not promise automatic cleanup or any specific retention period.
  • In Local mode the page itself submits no records to this site, so the logs only show requests for the page files.

Sign-in and keys

  • To sign in you sign a one-time message from the server with your Kaspa wallet, to prove you own the address. The message contains a random nonce and a time, can be used once, and is valid for a few minutes.
  • This signature creates no on-chain transaction and authorizes no transfer.
  • This site never asks for your private key or seed phrase. If anyone asks for them in this site’s name, do not provide them.
  • After a successful sign-in the server issues an HttpOnly session cookie with a limited lifetime (see “session lifetime”); leaving the cloud revokes it immediately.

Application logs

The application’s own log records warnings and above only, and never record content (names, notes, person, dose, batch). Keyword search uses the request body, so it never appears in a URL. See the IIS logs section above for web-server logs.

Your controls

  • Export all data: download JSON / CSV on the Data tab (both modes; the files are unencrypted, keep them safe).
  • Delete all data: on the Data tab, deletes all records in the current mode (two confirmations; the page offers no undo). What deletion really means, and how long backups are kept, is described above under “Deleting locally” and “Cloud mode: what deletion actually does”.

Other

The page loads no external scripts, fonts or analytics, and the browser content security policy (CSP) only allows connections to this site (in Local mode the page does not submit records even to this site). The QR scanner is a local component served with the site; the camera image is processed only in your browser and is never uploaded.
